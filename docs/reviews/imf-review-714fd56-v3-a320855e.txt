VERDICT
The repo is tidier than last round: packaging builds, the test suite grew and passes, and the README no longer oversells the benchmark tables. The core algebra is sound and I verified the phase-inversion math numerically. The main structural finding is a mismatch between the instrument the papers prove things about and the layer that ships: as implemented, FusedSAVGLayer is exactly a two-timescale decayed outer-product memory (closed form verified below), while Theorem 1 of paper 1 assumes dual probes and separate symmetric/antisymmetric readouts that the layer does not have. Separately, the repo's own directionality table currently reads against the headline claim: the SAVG variant shows higher reverse leakage and lower directional separation than the baseline, while the README and papers say the Reversal Curse is resolved. On generalization: no benchmark demonstrates a reliable above-baseline held-out lift; the held-out success counts are single digits on one seed and sit close to simple uniform-guess and constant-predictor references on this single run. The positive quantitative results I could verify are training-set fit and author-run latencies.

These are implementation, experiment and documentation findings. They do not touch the mathematics of the free symmetric/skew decomposition, which is correct as far as it goes. Do not read any item below as a verdict on the wider construction.

FINDINGS
Severity: HIGH first, then MEDIUM, then LOW. Fixes are directions, not mandates; where an item is a design note rather than a defect, it says so.

1. HIGH, DERIVED+RAN. As shipped, the fused SAVG layer is exactly a two-timescale decayed outer-product memory; the paper's dual-probe directional instrument is not what runs.
   triton_savg_kernel.py:65-66 (kernel) and :94-96 (reference) sum net = S_state + A_state and then apply the query. Since S + A = 0.5(uv^T + vu^T) + 0.5(uv^T - vu^T) = uv^T, the per-step increment recombines before readout. Note that uv^T itself is already orientation-sensitive once U and V are distinct learned projections (it maps v-directions to u-directions). What the split adds structurally in this wiring is only the reverse-orientation vu^T contribution, and that contribution is controlled entirely by the decay gap. With the shipped unequal decays (gamma_s = 0.999, gamma_a = 0.990, hardcoded at triton_savg_kernel.py:161) the output is precisely
      out_t = sum_tau g_tau [ c1(k) u_tau v_tau^T + c2(k) v_tau u_tau^T ] q_t,  k = t - tau,
      c1(k) = 0.5(gs^k + ga^k), c2(k) = 0.5(gs^k - ga^k),
   verified against the reference implementation in closed form (max abs diff 7.4e-6, B=2, T=12, D=8). The reverse-orientation coefficient relative to the forward one is c2/c1 = 0.00 at lag 0, 0.22 at lag 50, 0.72 at lag 200 for the shipped gammas. With equal decays c2 = 0 identically and the layer is algebraically equivalent to a plain single-decay outer-product scan, confirmed numerically within floating-point error (max abs diff 3.8e-6).
   The mismatch: Theorem 1 (papers/01, section 2.2) scores with two separate probes (q_u, q_v), a coupling lambda, and independent S and A readouts. FusedSAVGLayer has one readout of the summed state, and Q is an independent projection of x, so the theorem's hypothesis (query proportional to u) is not enforced anywhere in the layer. The phase-inversion result itself is correct where its assumptions hold (finding 16); the gap is between the proven instrument and the shipped wiring.
   Fix direction: either give the layer separate S and A readouts with the dual-probe scoring the theorem assumes, or state in the docs that the fused layer is a two-timescale outer-product memory and reserve the directional claims for a readout that keeps the sectors apart. Do not touch the decomposition math itself.

2. HIGH, READ. The headline claim contradicts the repo's own table.
   README.md:236-239 and papers/01:185-188: SAVG reverse leakage 18.8% vs baseline 6.2%, directional separation +0.7074 vs baseline +0.7194. Meanwhile README.md:53 says IMF "solves these challenges", papers/01:196 says SAVG "mathematically resolves the Reversal Curse", papers/03:121 calls it "a solved artifact of primitive linear algebra". On the numbers the repo publishes, the augmented model is currently slightly worse on the separation metric and about three times higher on reverse leakage. Paper 1 section 5.2 already hedges ("requires explicitly thresholded rejection heads"); the conclusions and README are the parts out of sync.
   Scope note: this is a single-seed, train-set probe (finding 8), so treat the table as preliminary evidence, not a refutation of the mechanism; but the wording should match the evidence either way.
   Fix direction: align the three conclusion statements with the tables, or rerun the probe after addressing finding 1 and update the tables.

3. MEDIUM, RAN. No benchmark demonstrates a reliable above-baseline held-out lift.
   Reproduced at this commit on CPU. 2-hop SPO: held-out accuracy 0.8% (baseline) and 1.6% (arity-3) out of 256 test chains, i.e. 2 and 4 successes. 3-hop: 0.0% and 0.4%, i.e. 0 and 1 successes.
   Reference baselines, computed at this commit (not assumed):
   - Uniform-guess reference: 1/128 = 0.78% (2-hop), 1/256 = 0.39% (3-hop). Uniform independent guessing has expected accuracy 1/N for any label distribution, so this reference is statistically valid here; it is just a weak comparator if labels are nonuniform.
   - Constant-predictor baseline (predict the train set's majority label): 1.17% on the 2-hop test set, 0.39% on the 3-hop test set. This is the stronger observed simple baseline.
   The models' held-out results sit close to these simple references on this single run: the arity-3 model's 1.6% (4 successes) is above the constant baseline's 1.17%, the pairwise baseline's 0.8% (2 successes) is below it, and all counts are within single-seed noise of each other. The honest summary is absence of evidence, not a calibrated at-chance verdict: no reliable above-baseline generalization is demonstrated, and the sample sizes (single seed, single-digit successes) cannot support a stronger statement in either direction. Train accuracy is 100% everywhere, so what the SPO scripts currently measure clearly is training-set fit.
   MQAR (published numbers, not rerun here): held-out 0.0-1.6% on 64 evaluation queries; uniform-guess reference 1/256 = 0.39%.
   Two validity problems with the SPO comparison itself:
   a. The "Pairwise Attention (Arity-2)" baseline degenerates to an MLP: its self-attention runs over a sequence of length 1 (benchmark_spo_multihop.py:40-45), where attention is an identity-weighted pass. The published speed win (1.76 ms vs 5.95 ms) is against that baseline, and it did not reproduce here: on CPU the arity-3 model was slightly slower (1.52 vs 1.24 ms 2-hop; 1.72 vs 1.48 ms 3-hop). There is also no warmup in benchmark_spo_multihop.py, so first-step costs land on whichever model runs first.
   b. Single seed everywhere; no mean or variance reported in any benchmark.
   Fix direction: report SPO as a capacity/memorization probe until a held-out split shows a statistically clear lift (multi-seed, report mean and std, and report the empirical constant-predictor baseline alongside the uniform 1/N reference); give the baseline a real sequence or rename it MLP; add warmup to the timing loop.

5. MEDIUM, READ. Paper 1 describes a tiled kernel the code does not contain; kernel scaling in d is untested.
   Papers/01:135 describes "sequence chunks into SRAM (Tile sizes B_M = 32, B_N = 32)". No such constants or tiling exist in triton_savg_kernel.py: the kernel keeps two BLOCK_D x BLOCK_D fp32 states per program with BLOCK_D = next_power_of_2(D) (:110), one program per batch item, T looped serially. As a logical size, at d_model = 512 those states are 2 x 512^2 x 4 B = 2 MB of values per program instance; how Triton would actually allocate or spill that, and at which d the kernel stops compiling, is untested here because there is no GPU in this environment. The verified part of this finding is the source/paper mismatch; the hardware behavior at large d is an open gate, not an asserted cap. Also note the docstring at :144 says "Production-ready", which is ahead of any demonstrated scaling data.
   Fix direction: correct paper 1 section 4.1 to describe the actual kernel; document intended d range once measured on GPU; soften "Production-ready".

6. MEDIUM, READ. Three different objects are all called SAVG.
   The kernel/FusedSAVGLayer: two decayed sectors, summed before readout (finding 1). The benchmarked wrapper in test_savg_harness.py:81 and benchmark_polytopes.py:60: antisymmetric-only, undecayed cumsum (gamma = 1), tanh-gated additive readout. Paper Theorem 1: dual-probe scoring with coupling lambda. Results from the wrapper do not measure the kernel, and neither matches the theorem's instrument. The undecayed cumsum also means the wrapper has no decay-based saturation control, while paper 1 section 2.3 motivates grid modulation as preventing unbounded state saturation.
   Fix direction: name the variants distinctly in code and papers, and run at least one benchmark against the actual FusedSAVGLayer update rule.

7. MEDIUM, RAN. Backward pass saves activation volume proportional to B.T.d^2 (measured).
   triton_savg_kernel.py:130-139 recomputes the full T-step reference scan with autograd enabled during backward. I measured the cumulative volume of tensors saved for backward with torch.autograd.graph.saved_tensors_hooks on CPU (B=2; T in {4,8,16,32}; d in {16,32}; script in Appendix A): saved elements ~= 3.3-3.6 x B.T.d^2 at every size, i.e. linear in T.d^2 (e.g. T=32, d=32: 215,168 elements). Two clarifications: this is cumulative saved-tensor volume across the unrolled graph, not measured peak live memory; and it characterizes the reference backward path the layer actually uses, independent of any GPU. The O(B.d^2) memory figure quoted in paper 1 section 4.2 is a forward-only property; training-side storage grows with sequence length times d squared.
   Fix direction: mark the bound forward-only in the paper; consider a custom backward (reverse pass with checkpointing) before training-at-scale claims.

8. MEDIUM, READ. Directionality probe has no held-out associations.
   test_savg_directionality.py:75: train_indices = range(16) covers all 16 pairs; forward "accuracy" 100% is training accuracy, and the reverse probe runs on the same pairs. Last round asked for a matched baseline and holdout; the baseline was added, the holdout was not. Related: the harness task in test_savg_harness.py (evaluate_synthetic_reasoning) predicts shifted random noise, so its printed "Loss Improvement with SAVG" is a memorization-of-noise number, not a reasoning signal.
   Fix direction: hold out half the pairs from forward training and probe on them; relabel or replace the noise-shift task.

9. DESIGN NOTE, READ. SPO transition map and comparator choice.
   benchmark_spo_multihop.py:71 and stress_spo_multihop.py:41: T(e, r) = (e(r+1) + (r+3)) mod N. For odd r, r+1 is even, so the map is non-injective modulo 128/256 and chains can merge on shared targets. This is not a correctness bug: the task remains a well-defined deterministic function, and nothing about multi-hop query tasks requires invertible relations. Measured on this commit's test sets, the 256 chains cover 104 distinct targets (2-hop) and 155 (3-hop); a finite sample missing some labels does not by itself prove the underlying target distribution is nonuniform, so this is reported as context for comparator choice (finding 3 reports both the uniform 1/N reference and the empirical constant-predictor baseline), not as a defect. Optional change only, if you want guaranteed-uniform targets: use a per-relation bijection (e.g. e -> (e + r + 1) mod N composed with a fixed permutation).

16. MATH NOTE, DERIVED+RAN. The algebra checks out; one historical analogy is asserted without a theorem.
   Verified numerically: paper 1 section 2.2's phase inversion for the orthogonal case, A u = -0.5||u||^2 v when u is orthogonal to v (max err 9.5e-7). Note this clean form needs orthogonality; for general u, v the expression is 0.5((v.u)u - ||u||^2 v), so the exact inversion is a property of the aligned/orthogonal regime, not a general statement about arbitrary readout directions. The Lean theorems are correct elementary ring identities over Int with doubled sectors (2M = 2S + 2A); the files themselves note the normalized split needs halving, i.e. Q or R. What the proofs establish is the decomposition's algebra, not any property of the trained layer's behavior.
   The one weak spot: papers/03 section 2.2 presents dimensions 9-11 as "the precise boundary where normed algebraic stability interfaces with multi-dimensional combinatorial freedom", in the context of Degen's identity and Hurwitz's theorem. Hurwitz's theorem bounds normed division algebras (composition algebras) at dimensions 1, 2, 4, 8 (reference: https://en.wikipedia.org/wiki/Hurwitz%27s_theorem_(composition_algebras), fetched at review time); no theorem is supplied in the paper connecting that bound to the 9-11 choice. The dimensions may well be good engineering picks; the paper just does not establish a mathematical reason, so the "precise boundary" phrasing should be softened or a citation added.

APPENDIX A: saved-activation volume measurement script (finding 7)
Save as a .py file in the repo root and run it there with torch installed (verified reproducing at this commit). Counts every tensor autograd saves for backward through the reference scan; prints the ratio to B*T*d^2.

  import torch
  from triton_savg_kernel import pytorch_reference_savg_scan
  from torch.autograd.graph import saved_tensors_hooks

  B = 2
  print("T   d   saved_elems  elems/(B*T*d^2)")
  for T in [4, 8, 16, 32]:
      for d in [16, 32]:
          torch.manual_seed(0)
          U = torch.randn(B, T, d, requires_grad=True)
          V = torch.randn(B, T, d, requires_grad=True)
          Q = torch.randn(B, T, d, requires_grad=True)
          g = torch.rand(B, T, requires_grad=True) + 0.5
          saved = [0]
          def pack(t):
              saved[0] += t.numel()
              return t
          with saved_tensors_hooks(pack, lambda t: t):
              out = pytorch_reference_savg_scan(U, V, Q, g)
          out.sum().backward()
          print(f"{T:3d} {d:3d}  {saved[0]:10d}  {saved[0]/(B*T*d*d):8.2f}")
