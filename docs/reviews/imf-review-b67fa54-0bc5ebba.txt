======================================================================
HEADLINE VERDICT
======================================================================
The repo is a small research prototype with a correct algebra core (the Lean identities and the S/A decomposition are fine as stated). The headline results in the README and in the new papers/ (2.47x directional margin, 0.74 ms / 6.59x speedup, "noise immune", 96.8% at N=4096, 99.4% multi-hop, 0% collisions, "resolves the Reversal Curse", "formally verified") are not supported by anything in the repo, and several of the committed benchmarks cannot support them by design:
 - the SPO benchmarks feed the answer in as an input;
 - the MQAR task can be solved from the query token alone (a linear head with no context reaches 100%);
 - the directionality test uses random input and untrained models;
 - the Triton layer has no backward, so its input maps would not train;
 - the papers' Lean excerpts end in `sorry` and name theorems that do not exist in the repo's Lean files.
The identities that are in the repo (sym/antisym split, orthogonality, energy partition over Int) are correct as stated. The issue is what is claimed on top of them and the evidence offered. Nothing here shows the ideas are wrong; it shows the headline claims are not established by the committed evidence and have not yet been tested by a design that could fail.

2.1 Which readout is intended, and what does S+A add? [RAN-H + READ]
    S + A = u v^T exactly (RAN-H). The Triton kernel reads out[i] = sum_j net_state[i,j] q[j] = (net_state @ q) (triton_savg_kernel.py L83, axis=1) with net_state = S_state + A_state (L82). With equal decay that is (u v^T) q = u (v . q): v is the key and u the value. A read with q=v returns u (cosine 1.000); q=u returns u scaled by (v . u), so for random non-orthogonal u, v the cosine with v is only 0.076 (RAN-H). So a plain outer-product memory is already directional in this convention (key to value); README L49 ("treat keys symmetrically") and the papers' "directional conflation" description do not match M = sum v k^T for this read (RAN-H used random, non-orthogonal u, v: cosines 1.000 and 0.076 for the two reads). README L103-107 states A u ∝ -v and A v ∝ +u. With A = (u v^T - v u^T)/2 acting on column vectors, the exact expressions are A u = (u (v.u) - v |u|^2)/2 and A v = (u |v|^2 - v (u.v))/2. So A u ∝ -v and A v ∝ u hold only when u and v are orthogonal (v.u = 0, then A u = -|u|^2 v / 2 and A v = |v|^2 u / 2), or in degenerate cases; for non-orthogonal u, v each result also contains a component along the probe itself. The README states the relations without that assumption (README L103-109). README L109 then says "By combining (S - A)" cancels reverse recall, but the kernel reads S + A (L82); with S - A the roles of the two reads swap (RAN-H).
    papers/01 Theorem 1 (from L66) scores probes as u^T M v with M = S + lambda A for one stored pair. Exact values: u^T A v = (|u|^2 |v|^2 - (u.v)^2)/2, which is >= 0 by Cauchy-Schwarz and zero only when u, v are parallel, and v^T A u = -u^T A v; u^T S v = v^T S u = (|u|^2 |v|^2 + (u.v)^2)/2. So S_fwd - S_rev = 2 lambda S_A is exact. But "reverse score becomes negative, completely extinguishing backward recall" requires lambda S_A > S_S, i.e. lambda (|u|^2 |v|^2 - (u.v)^2) > |u|^2 |v|^2 + (u.v)^2. Since S_S - S_A = (u.v)^2 >= 0, S_A <= S_S, so lambda > 1 is necessary; for lambda = 1 and orthogonal u, v the reverse score is exactly 0 (cancellation); for other probes and lambda <= 1 the reverse score is suppressed, not cancelled. Multi-pair accumulation with decay, gating and noise changes this further and is not covered by the single-pair statement. The code also differs from the theorem: it returns a vector (S+A) q with no lambda, while the theorem scores a scalar bilinear form. Question: which is the intended SAVG readout, in which key/value roles are the forward and reverse reads meant, and under what assumption on the probes (orthogonality, lambda) is exact cancellation claimed rather than suppression? With equal decay and S+A the split carries no information beyond the plain outer product; the only difference in the kernel is gamma_s = 0.999 vs gamma_a = 0.990 (L94-95; L77-78).
